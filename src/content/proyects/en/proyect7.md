## 📌 Engineering Summary
Memo.ai is an intelligent educational ecosystem designed to transform massive document ingests (PDFs, audio recordings, and transcripts) into personalized study copilots. The architecture resolves information overload through asynchronous, structured data processing, semantic indexing, and Retrieval-Augmented Generation (RAG). The system is orchestrated as a distributed monorepo using microservices, optimized for performance via multi-tier caching and fine-tuned concurrency.

## 🏗️ System Architecture & Technical Decisions
* **Frontend:** Built on Next.js utilizing Server-Side Rendering (SSR) and Static Site Generation (SSG). High-performance interactive flows were developed using Motion (Framer Motion) and Shadcn/UI, enabling selective client-side rendering of dynamic components and persistent layout state without main-thread overhead.
* **Backend & Microservices:** Designed under a decoupled architecture. The core transacting API is built with NestJS (TypeScript), managing authentication via Better Auth and fast persistence. Heavy AI processing and ETL workflows are offloaded to an asynchronous FastAPI (Python 3.11) microservice, avoiding bottlenecks on the Node.js event loop.
* **Data & Vector Layer:** Structured persistence in serverless PostgreSQL (Neon) using Drizzle ORM. A vector database was integrated to store semantic embeddings generated by OpenAI/Cohere models, utilizing LangChain and optimizing cosine similarity searches via HNSW indexing.
* **Infrastructure & Cache:** Workspace management orchestrated with Turborepo, speeding up local builds and CI/CD runs by 40%. A Redis cluster (Cache-manager) caches redundant RAG fragments and session states, reducing database traffic. Heavy file assets are handled securely through AWS S3 pre-signed URLs and UploadThing.

## 🚀 Technical Challenges & Impact Metrics
* **RAG Response Latency:** Reduced chatbot response times by 65% (from 3.5s to <1.2s for first-token response and streaming SSE tokens at <80ms perceived latency) by building a hybrid pipeline that pre-processes queries and caches hot vector contexts in Redis.
* **Large Document Processing:** Cut memory footprint by 50% when processing PDFs exceeding 50 pages by streaming extraction and implementing dynamic chunking via PyMuPDF and recursive LangChain Text Splitters in Python.
* **Monorepo Type Safety:** Zero runtime type errors across Next.js, NestJS, and the database layer by centralizing data contracts using shared Zod schemas and strict compile-time types from Drizzle ORM.
